Объяснение мышления для Lab 2

Почему такая последовательность?

1. network_info -> whois_checker первыми
Ошибка новичка: Начинать с port_check
Правильно: Начинать с network_info

Почему?
network_info показывает где физически сервер
whois_checker показывает кто владелец
Без этой информации сканирование портов слепое
Можно нарушить закон сканируя не ту сеть

2. port_check вторым
Ошибка новичка: Пропустить или сделать слишком поздно
Правильно: После разведки, до анализа сервисов

Почему?
Теперь есть контекст для портов
Знаем что цель легальная для сканирования
Понимаем сетевую среду

3. ssl_checker + web_scanner третьими
Ошибка новичка: Запустить dir_buster сразу после port_check
Правильно: Сначала анализ, потом dir_buster если нужно

Почему?
web_scanner покажет что за сервис Apache, Nginx
ssl_checker покажет проблемы с шифрованием
Без этой информации dir_buster будет слепым
90% запросов dir_buster будут бесполезными

4. cve_lookup последним
Ошибка новичка: Запустить cve_lookup без данных
Правильно: Сначала собрать все данные о сервисах

Почему?
cve_lookup требует точные названия и версии сервисов
Без web_scanner не знаешь что искать
Без port_check не знаешь какие сервисы есть

Как связывать порты с уязвимостями
Памятка для мышления:

Порт 80/443 -> Веб-сервер -> web_scanner -> версия -> cve_lookup
Порт 22 -> SSH -> анализ баннеров -> версия -> cve_lookup
Порт 21 -> FTP -> анализ баннеров -> версия -> cve_lookup

Важно: Не все порты требуют одинакового анализа.
Веб-порты 80,443,8080,8443 требуют web_scanner.
Остальные порты требуют анализа баннеров и cve_lookup.

Когда dir_buster лишний
Когда еще не сделал web_scanner
Когда время ограничено
Когда цель простая можно найти уязвимости проще
Когда уже нашел критические уязвимости другими способами

Правило: Сначала быстрый анализ, потом глубокий.
