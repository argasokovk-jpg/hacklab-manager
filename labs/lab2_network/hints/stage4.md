Этап 4: Поиск уязвимостей

Цель этапа
Найти известные уязвимости для обнаруженных сервисов.

Вопрос для мышления
Как связать найденные порты с потенциальными уязвимостями?

Инструмент
hl cve_lookup [сервис] [версия]

Связь портов с уязвимостями
Каждый порт -> определенный сервис -> определенные уязвимости

Порт 80/443 -> Веб-сервер -> Тип: Apache -> Версия: 2.4.41
-> CVE-2021-40438 уязвимость в mod_proxy
-> CVE-2021-41773 путь обхода

Порт 22 -> SSH сервер -> Тип: OpenSSH -> Версия: 8.2
-> CVE-2020-14145 уязвимость аутентификации
-> CVE-2019-6111 обход проверки

Порт 21 -> FTP сервер -> Тип: vsftpd -> Версия: 3.0.3
-> CVE-2011-0762 уязвимость доступа

Что нужно для cve_lookup
Сервис из port_check + web_scanner
Версия из web_scanner или баннеров
Конфигурация из ssl_checker и анализа

Пример полной цепочки
1. port_check -> порт 443 открыт
2. ssl_checker -> TLS 1.3, сертификат валиден
3. web_scanner -> Apache 2.4.41, Ubuntu, PHP 7.4
4. cve_lookup apache 2.4.41 -> находим CVE
5. cve_lookup php 7.4 -> находим CVE

Типичная ошибка
Запускать cve_lookup без данных о сервисах.
Нельзя искать уязвимости если не знаешь что искать.

Что делать если нет точной версии
Используй приблизительную версию Apache 2.4.x
Проверь общие уязвимости для сервиса
Сфокусируйся на конфигурационных ошибках
Проверь стандартные уязвимости для порта
