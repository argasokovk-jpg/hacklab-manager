Этап 3: Анализ сервисов

Цель этапа
Детально изучить найденные сервисы.

Вопрос для мышления
Когда dir_buster лишний на этом этапе?

Инструменты
Для порта 443: hl ssl scanme.nmap.org
Для портов 80/443: hl web scanme.nmap.org

Когда dir_buster лишний
Когда еще не определили веб-сервер
Когда сервер статический
Когда время ограничено
Когда цель простая

Сначала всегда делай
web_scanner: узнай что за сервер, технологии
ssl_checker: проверь безопасность соединения
Потом решай: нужен ли dir_buster

Что искать в web_scanner
Тип веб-сервера Apache, Nginx, IIS
Версия сервера
Используемые технологии PHP, Python, Node.js
Заголовки HTTP
Возможные информационные утечки

Что искать в ssl_checker
Версии SSL/TLS протоколов
Используемые шифры
Сертификат валидность, срок действия
Возможные уязвимости Heartbleed, POODLE

Пример правильного подхода
1. Нашел порт 443 -> запускаю ssl_checker
2. SSL нормальный -> запускаю web_scanner
3. Узнаю что сервер Apache 2.4 -> запоминаю для cve_lookup
4. Решаю: Нужен ли dir_buster? Может сначала проверить cve для Apache?

Типичная ошибка
Запускать dir_buster сразу после port_check.
Вместо тысячи запросов наугад, лучше 10 целенаправленных проверок.
